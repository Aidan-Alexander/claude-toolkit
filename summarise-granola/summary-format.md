# Summary format (detailed)

Write a comprehensive, chronological summary that helps the user re-live and remember the conversation. The chronological structure is the key: by following the flow, the user can recall details the summary doesn't spell out.

## Document structure

```markdown
# Call summary: [Title]

**Date:** YYYY-MM-DD

**Participants:** [Full names, with roles where relevant]

**Granola note:** [link]

## Summary

[3–5 sentences on what the call was about and what was concluded. If you list items, use a numbered list with each item on its own line.]

## Part 1: [Opening topic or context]

[Chronological narrative of this phase of the conversation...]

## Part 2: [Next major topic]

[Continue chronologically...]

## Part N: Next steps

[Clear statement of the decisions made and the actions agreed]

**Actions agreed:**
1. First action (owner)
2. Second action (owner)

## Appendix 1: Open questions

- Question 1
- Question 2

## Appendix 2: Key quotes

| Speaker | Quote | Context |
|---------|-------|---------|
| Name | "Quote text" | Brief context |

## Appendix 3: Underlying dynamics

[Optional. Include it when there's real subtext, emotional undercurrent or strategic consideration worth noting. Skip it otherwise.]

**[Dynamic 1]:** Explanation...
```

If Granola's title isn't useful (a calendar placeholder, or just "Meeting"), write a short, descriptive one.

## Formatting

**Lists**
- Use numbered lists when items might be referred to later (options, actions, decisions).
- Use lettered lists (a, b, c) when you don't want to imply an order of priority.
- Use bullets only for items nobody will need to refer back to.
- Put each list item on its own line.

**Quotations**
- Use inline "quotation marks" for short key phrases within the prose.
- Use a block quote for longer or especially important statements.
- Keep the exact wording for:
  - expressions of certainty or uncertainty;
  - commitments and decisions;
  - memorable or distinctive phrasing;
  - insights and realisations.

**Structure**
- Bold a speaker's name when you attribute a quote or position to them.
- Use tables for structured comparisons, such as options weighed against each other.

## Content

**Depth:** match it to the richness of the conversation. A substantive 45-minute strategy discussion warrants 2,000–4,000 words; a brief check-in might need a few hundred.

**Chronological narrative:** tell the story of how the conversation unfolded and how conclusions were reached. This is what lets the user reconstruct the call in their head.

**Capture insights:** don't just list decisions. Capture the reasoning, realisations and shifts in thinking that led to them.

**Appendices:**
- Open questions (Appendix 1): almost always include.
- Key quotes (Appendix 2): include when there are memorable or important phrasings.
- Underlying dynamics (Appendix 3): include only when there's something real to say.

## Example part

```markdown
## Part 2: Diagnosing the problem

**Jane** asked the pivotal question: "Is this a brief issue or an execution of the brief issue?"

That opened up the key realisation. Jane introduced the "new aesthetics" framing: an emerging visual language the project could have led on.

**Sam** recognised it straight away:
> "We should be at the front of that. In my dream world, if I was leading this, I would have put a lot into trying to be at the front of that."

**The diagnosis:** the brief hadn't communicated this ambition. Sam admitted it "definitely wasn't pitched that ambitiously", which explained the gap between what Sam had hoped for and the competent-but-safe work the agency delivered.
```
